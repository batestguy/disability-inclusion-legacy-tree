# Repository Guidelines

## Latest owner direction — 25 October 2026

Free tier only; the owner and Codex are the project team. Do not make progress
depend on hiring or outside sign-off. Keep unverified Hausa wording visibly draft
and record checks/owner feedback honestly rather than claiming certification.
The owner now requests a clickable question tree/flowchart with answers and
follow-up options instead of making free-text understanding the primary flow.
See docs/GUIDED_CHAT_IMPLEMENTATION.md. Earlier external-review requirements are
superseded by this direction; source integrity, reuse rights and truthful review
status remain required. Do not silently set approval flags or deploy publicly.

## Chatbot continuation requirements

Read docs/CHATBOT_SPEC.md before chatbot or dashboard work. The owner requires a polished conversational English/Hausa chatbot, built before dashboard integration, automatically following the page locale. Always display **Change language / Canja harshe** with **English** above **Hausa**, vertically stacked and visible without a menu. One shared control changes page and chat together. These are accepted requirements, not implemented features; human Hausa review and existing numerical/evidence/reveal gates remain required.

Preserve HonAbbas.txt as the original brief. PROJECT_PLAN.md records decisions and launch gates.
Use npm.cmd on Windows. The public application is apps/web; studio is the standalone Sanity editor.
Start continuations with HANDOFF.md; update it and relevant status documents before handing work back.
Never publish unsupported claims, translate drafts as approved, or use photographs without recorded reuse permission.
Keep credentials outside this repository. Static builds use public, reviewed content only.
Run npm run lint, npm run typecheck, npm test, and npm run build before delivery.
Public reveal requires an approved genuine portrait and human Hausa review. Record limits honestly.
